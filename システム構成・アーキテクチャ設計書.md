## レイヤードアーキテクチャ詳細

Spring Bootで推奨される**レイヤードアーキテクチャ**を採用します。各層は明確な責務を持ち、依存関係は上位層→下位層の一方向です。

### Presentation Layer（プレゼンテーション層）

**役割**: HTTPリクエストの受付とレスポンス返却

**コンポーネント**:
- `@RestController`: REST APIエンドポイント
- `@ControllerAdvice`: グローバル例外ハンドリング
- DTO (Data Transfer Object): リクエスト/レスポンス用のデータ構造

**責務**:
- リクエストのバリデーション（`@Valid`）
- DTOとエンティティの変換
- HTTPステータスコードの設定
- 認証情報の取得（`@AuthenticationPrincipal`）

**依存**: Service Layer

**実装例**:
```java
@RestController
@RequestMapping("/api/reservations")
public class ReservationController {

    private final ReservationService reservationService;

    public ReservationController(ReservationService reservationService) {
        this.reservationService = reservationService;
    }

    @PostMapping
    public ResponseEntity<ReservationResponse> createReservation(
        @Valid @RequestBody CreateReservationRequest request,
        @AuthenticationPrincipal CustomUserDetails userDetails
    ) {
        ReservationResponse response = reservationService.createReservation(
            request.getSlotId(),
            userDetails.getUserId()
        );
        return ResponseEntity.status(HttpStatus.CREATED).body(response);
    }
}
```

### Domain Layer（ドメイン層）

**役割**: データモデルとデータアクセス

**コンポーネント**:
- `@Entity`: JPA エンティティ
- `@Repository`: データアクセスインターフェース（Spring Data JPA）

**責務**:
- データベーステーブルとのマッピング
- CRUD操作の定義
- カスタムクエリ（JPQL, Native Query）

**依存**: なし（最下層）

**実装例（Entity）**:
```java
@Entity
@Table(name = "reservations")
public class Reservation {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "slot_id", nullable = false)
    private Slot slot;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "user_id", nullable = false)
    private User user;

    @Enumerated(EnumType.STRING)
    @Column(nullable = false)
    private ReservationStatus status;

    @Column(name = "google_calendar_event_id")
    private String googleCalendarEventId;

    // created_at, updated_at, getters, setters...
}
```

**実装例（Repository）**:
```java
@Repository
public interface ReservationRepository extends JpaRepository<Reservation, Long> {

    List<Reservation> findByUserIdAndStatus(Long userId, ReservationStatus status);

    Long countBySlotIdAndStatus(Long slotId, ReservationStatus status);

    @Query("SELECT r FROM Reservation r " +
           "JOIN FETCH r.slot s " +
           "WHERE r.userId = :userId")
    List<Reservation> findByUserIdWithSlot(@Param("userId") Long userId);
}
```

### Infrastructure Layer（インフラストラクチャ層）

**役割**: 横断的関心事、外部システム連携

**コンポーネント**:
- `@Configuration`: 各種設定クラス
- Security Config: Spring Security設定
- Mail Config: JavaMailSender設定
- External API Client: Google API クライアント

**責務**:
- 認証・認可の設定
- CORS設定
- メール送信設定
- Google API認証・呼び出し

**実装例（Security Config）**:
```java
@Configuration
@EnableWebSecurity
public class SecurityConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/slots/**").permitAll() // 予約枠一覧は公開
                .requestMatchers("/api/reservations/**").hasRole("USER")
                .requestMatchers("/api/staff/**").hasRole("STAFF")
                .anyRequest().authenticated()
            )
            .oauth2Login(oauth2 -> oauth2
                .successHandler(oAuth2SuccessHandler)
            )
            .csrf(csrf -> csrf.csrfTokenRepository(CookieCsrfTokenRepository.withHttpOnlyFalse()));

        return http.build();
    }
}
```

## 主要な設計原則

### 1. 依存性注入（DI）

- すべてのコンポーネントは`@Component`, `@Service`, `@Repository`でSpringコンテナに登録
- **コンストラクタインジェクション**を推奨（`@Autowired`は使わない）

**推奨例**:
```java
@Service
public class ReservationService {
    private final ReservationRepository reservationRepository;
    private final SlotRepository slotRepository;
    private final GoogleCalendarService calendarService;

    // コンストラクタインジェクション
    public ReservationService(
        ReservationRepository reservationRepository,
        SlotRepository slotRepository,
        GoogleCalendarService calendarService
    ) {
        this.reservationRepository = reservationRepository;
        this.slotRepository = slotRepository;
        this.calendarService = calendarService;
    }
}
```

**理由**:
- テストしやすい（Mockを注入しやすい）
- 依存関係が明確
- final フィールドにできる（不変性）

---

### 2. DTOパターン

- エンティティを直接APIレスポンスとして返さない
- セキュリティ（機密情報の隠蔽）とAPIの安定性のため

**悪い例**:
```java
@GetMapping("/users/{id}")
public User getUser(@PathVariable Long id) {
    return userRepository.findById(id); // ❌ Entityをそのまま返す
}
```

**良い例**:
```java
@GetMapping("/users/{id}")
public UserResponse getUser(@PathVariable Long id) {
    User user = userRepository.findById(id);
    return new UserResponse(user); // ✅ DTOに変換して返す
}
```

**理由**:
- パスワード等の機密情報を隠蔽
- エンティティの変更がAPIに影響しない
- レスポンスの形を自由に設計できる

---

### 3. トランザクション管理

- サービス層のメソッドに`@Transactional`を付与
- 読み取り専用の場合は`@Transactional(readOnly = true)`

**実装例**:
```java
@Service
public class ReservationService {

    @Transactional // 書き込みトランザクション
    public ReservationResponse createReservation(Long slotId, Long userId) {
        // 予約作成処理（INSERT/UPDATE）
    }

    @Transactional(readOnly = true) // 読み取り専用
    public List<ReservationResponse> getMyReservations(Long userId) {
        // 予約一覧取得（SELECT のみ）
    }
}
```

**理由**:
- ACID特性の保証
- ロールバック自動処理
- readOnlyでパフォーマンス最適化

---

### 4. 楽観ロック

- `Slot`エンティティに`@Version`を付与
- 同時予約時の定員超過を防止

**実装例**:
```java
@Entity
public class Slot {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Version // 楽観ロック用
    private Long version;

    private Integer capacity;
    // ...
}
```

**処理フロー**:
1. 予約作成時にSlotを取得（versionも取得）
2. 予約数をカウント、定員チェック
3. Reservationを保存
4. Slotを更新（versionが自動インクリメント）
5. 同時実行時にversionが変わっていたら`OptimisticLockException`発生

**理由**:
- 定員超過の絶対防止（最重要要件）
- 悲観ロックより性能が良い
- Spring Data JPAで簡単に実装可能

---

### 5. 例外ハンドリング

- カスタム例外を定義
- `@ControllerAdvice`でグローバルハンドリング

**カスタム例外**:
```java
public class SlotFullException extends BusinessException {
    public SlotFullException() {
        super("満席になりました");
    }
}
```

**グローバルハンドラ**:
```java
@ControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(SlotFullException.class)
    public ResponseEntity<ErrorResponse> handleSlotFull(SlotFullException ex) {
        ErrorResponse error = new ErrorResponse(
            "SLOT_FULL",
            ex.getMessage()
        );
        return ResponseEntity.status(HttpStatus.CONFLICT).body(error);
    }

    @ExceptionHandler(OptimisticLockException.class)
    public ResponseEntity<ErrorResponse> handleOptimisticLock(OptimisticLockException ex) {
        ErrorResponse error = new ErrorResponse(
            "CONCURRENT_ACCESS",
            "同時にアクセスがありました。再度お試しください"
        );
        return ResponseEntity.status(HttpStatus.CONFLICT).body(error);
    }
}
```

### 1. Google Calendar API

**サービス層で抽象化**:

```java
@Service
public class GoogleCalendarService {

    public String createEvent(User user, Slot slot, String menuName) {
        // 1. user.googleAccessToken を使用してGoogle Calendar APIクライアント作成
        // 2. イベント作成リクエスト送信
        // 3. 作成されたevent_idを返す
        return eventId;
    }

    public void deleteEvent(User user, String eventId) {
        // 1. user.googleAccessToken を使用してGoogle Calendar APIクライアント作成
        // 2. イベント削除リクエスト送信
    }
}
```

**エラーハンドリング**:
- カレンダー連携失敗でも予約処理は成功扱い
- try-catchでエラーログ記録
- ユーザーに警告メッセージ表示

**実装例**:
```java
@Transactional
public ReservationResponse createReservation(Long slotId, Long userId) {
    // 予約作成処理
    Reservation reservation = // ...

    // Google Calendar連携（失敗しても予約は成功）
    if (user.getGoogleSub() != null) {
        try {
            String eventId = calendarService.createEvent(user, slot, menuName);
            reservation.setGoogleCalendarEventId(eventId);
        } catch (Exception e) {
            log.error("Google Calendar連携失敗: {}", e.getMessage());
            // 予約は成功、カレンダー連携のみ失敗
        }
    }

    return new ReservationResponse(reservation);
}
```

## ロギング戦略

### ログレベル定義

| ログレベル | 用途 | 例 |
|----------|------|-----|
| ERROR | システムエラー、例外 | DB接続失敗、Google API呼び出し失敗 |
| WARN | ビジネスルール違反 | 定員超過、キャンセル期限切れ |
| INFO | 主要操作 | ログイン、予約作成、キャンセル |
| DEBUG | デバッグ情報 | SQL発行、APIリクエスト詳細 |

### ログフォーマット

**Logback設定（logback-spring.xml）**:
```xml
<configuration>
```

## 開発環境構築

### Docker Compose構成

**docker-compose.yml**:

```yaml
version: '3.8'

services:
  # PostgreSQL
  postgres:
    image: postgres:13
    container_name: reservation_postgres
    environment:
      POSTGRES_DB: reservation_db
      POSTGRES_USER: reservation_user
      POSTGRES_PASSWORD: password
    ports:
      - "5432:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data
    networks:
      - reservation_network

  # MailHog（メールテスト用）
  mailhog:
    image: mailhog/mailhog
    container_name: reservation_mailhog
    ports:
      - "1025:1025"  # SMTP
      - "8025:8025"  # Web UI
    networks:
      - reservation_network

volumes:
  postgres_data:

networks:
  reservation_network:
    driver: bridge
```

### application.yml（Spring Boot設定）

```yaml
spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/reservation_db
    username: reservation_user

      ddl-auto: update  # 開発環境のみ。本番はvalidate

      hibernate:
        format_sql: true
```
