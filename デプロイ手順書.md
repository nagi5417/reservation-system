## 2. 事前準備

### 2.1 必要なもの

- **EC2インスタンス**: Amazon Linux 2023
- **SSH秘密鍵**: `~/.ssh/nagi5417-key.pem`
- **Vercelアカウント**: GitHubリポジトリと連携済み
- **GitHubリポジトリ**: https://github.com/nagi5417/reservation-system

### 2.2 EC2のセキュリティグループ設定

以下のインバウンドルールを設定：

| タイプ | ポート | ソース | 用途 |
|-------|-------|--------|------|
| SSH | 22 | マイIP | SSH接続 |
| カスタムTCP | 8080 | 0.0.0.0/0 | APIアクセス |

### 2.3 EC2にDockerとJavaをインストール

```bash
# EC2に接続
ssh -i ~/.ssh/nagi5417-key.pem ec2-user@18.183.192.121

# Dockerインストール
sudo yum update -y
sudo yum install -y docker
sudo systemctl start docker
sudo systemctl enable docker
sudo usermod -aG docker ec2-user

# Docker Composeインストール
sudo curl -L "https://github.com/docker/compose/releases/latest/download/docker-compose-$(uname -s)-$(uname -m)" -o /usr/local/bin/docker-compose
sudo chmod +x /usr/local/bin/docker-compose

# Javaインストール
sudo yum install -y java-17-amazon-corretto
```

## 3. バックエンド（EC2）デプロイ

### 3.1 JARファイルのビルド

ローカルマシンで実行：

```bash
cd /Users/yanagitanaoki/Documents/ReservationSystem/reservation

# クリーンビルド
./gradlew clean bootJar
```

ビルド成功後、`build/libs/reservation-0.0.1-SNAPSHOT.jar` が生成される。

### 3.2 JARファイルをEC2に転送

```bash
scp -i ~/.ssh/nagi5417-key.pem \
  ./build/libs/reservation-0.0.1-SNAPSHOT.jar \
  ec2-user@18.183.192.121:~/reservation.jar
```

### 3.3 EC2でアプリケーションディレクトリを作成

```bash
ssh -i ~/.ssh/nagi5417-key.pem ec2-user@18.183.192.121

# アプリケーションディレクトリ作成
sudo mkdir -p /opt/reservation
sudo cp ~/reservation.jar /opt/reservation/app.jar
```

### 3.4 systemdサービスファイルの作成

```bash
sudo vi /etc/systemd/system/reservation.service
```

内容：
```ini
[Unit]
Description=reservation backend
After=network.target

[Service]
Type=simple
User=ec2-user
WorkingDirectory=/opt/reservation
ExecStart=/usr/bin/java -jar /opt/reservation/app.jar
Restart=always
RestartSec=10

# 環境変数
Environment=SPRING_PROFILES_ACTIVE=prod
Environment=DB_HOST=localhost
Environment=DB_PORT=5432
Environment=DB_NAME=reservation_db
Environment=DB_USERNAME=reservation_user
Environment=DB_PASSWORD=reservation_pass
Environment=APP_BASE_URL=https://reservation-system-liart.vercel.app

[Install]
WantedBy=multi-user.target
```

### 3.5 PostgreSQLコンテナの起動

```bash
# docker-compose.ymlを作成（またはローカルからコピー）
cd /opt/reservation

# PostgreSQL起動
docker-compose up -d
```

### 3.6 サービスの起動

```bash
# サービスを有効化・起動
sudo systemctl daemon-reload
sudo systemctl enable reservation
sudo systemctl start reservation

# 状態確認
sudo systemctl status reservation
```

### 3.7 デプロイ更新時の手順

```bash
# ローカルでビルド
./gradlew clean bootJar

# EC2に転送
scp -i ~/.ssh/nagi5417-key.pem \
  ./build/libs/reservation-0.0.1-SNAPSHOT.jar \
  ec2-user@18.183.192.121:~/reservation.jar

# EC2でコピー＆再起動
ssh -i ~/.ssh/nagi5417-key.pem ec2-user@18.183.192.121 \
  "sudo cp ~/reservation.jar /opt/reservation/app.jar && sudo systemctl restart reservation"
```

## 4. フロントエンド（Vercel）デプロイ

### 4.1 Vercelプロジェクトの設定

1. [Vercel](https://vercel.com)にログイン
2. 「New Project」→ GitHubリポジトリを選択
3. 設定：
   - **Framework Preset**: Vite
   - **Root Directory**: `reservation-frontend`
   - **Build Command**: `npm run build`
   - **Output Directory**: `dist`

### 4.2 vercel.jsonの設定（重要）

`reservation-frontend/vercel.json`:

```json
{
  "rewrites": [
    {
      "source": "/api/:path*",
      "destination": "http://18.183.192.121:8080/api/:path*"
    },
    {
      "source": "/oauth2/:path*",
      "destination": "http://18.183.192.121:8080/oauth2/:path*"
    },
    {
      "source": "/login/oauth2/:path*",
      "destination": "http://18.183.192.121:8080/login/oauth2/:path*"
    }
  ]
}
```

**この設定が重要な理由：**
- Vercel（HTTPS）からEC2（HTTP）への直接リクエストは「Mixed Content」エラーでブロックされる
- Vercelのrewrite機能を使い、Vercelがプロキシとしてリクエストを中継することで解決

### 4.3 デプロイの実行

GitHubにプッシュすると自動でデプロイされる：

```bash
git add .
git commit -m "deploy: Vercel設定追加"
git push origin main
```

## 5. 発生した問題と解決策

### 5.1 Mixed Content エラー

#### 症状
ブラウザのコンソールに以下のエラーが表示される：

```
Mixed Content: The page at 'https://reservation-system-liart.vercel.app/'
was loaded over HTTPS, but requested an insecure XMLHttpRequest endpoint
'http://18.183.192.121:8080/api/slots'. This request has been blocked;
the content must be served over HTTPS.
```

#### 原因
- Vercel（HTTPS）からEC2（HTTP）への直接リクエスト
- ブラウザのセキュリティポリシーでブロックされる

#### 解決策
**Vercelプロキシを設定**

`vercel.json`でrewritesを設定し、VercelがEC2へのリクエストを代理で送信するようにした。

```
ブラウザ → Vercel (HTTPS) → Vercelプロキシ → EC2 (HTTP)
                ↑
          ここでHTTPSが終端されるのでMixed Contentにならない
```

### 5.2 CORS エラー

#### 症状
```
Access to XMLHttpRequest at 'http://18.183.192.121:8080/api/slots'
from origin 'https://reservation-system-liart.vercel.app'
has been blocked by CORS policy
```

#### 原因
- バックエンドのCORS設定にVercelドメインが含まれていなかった

#### 解決策
`SecurityConfig.java`のCORS設定にVercelドメインを追加：

```java
@Bean
public CorsConfigurationSource corsConfigurationSource() {
    CorsConfiguration configuration = new CorsConfiguration();
    configuration.setAllowedOrigins(Arrays.asList(
        "http://localhost:5173",
        "https://reservation-system-liart.vercel.app"  // 追加
    ));
    configuration.setAllowedMethods(Arrays.asList("GET", "POST", "PUT", "DELETE", "OPTIONS"));
    configuration.setAllowedHeaders(Arrays.asList("*"));
    configuration.setAllowCredentials(true);
    // ...
}
```

### 5.3 API 401エラー（認証不要APIなのに認証エラー）

#### 症状
`/api/service-menus` が401 Unauthorizedを返す（本来は認証不要のはず）

#### 原因
`SecurityConfig.java`のエンドポイントパスが間違っていた：

```java
// 間違い
.requestMatchers(HttpMethod.GET, "/api/menus/**").permitAll()

// 正しい（実際のエンドポイント）
.requestMatchers(HttpMethod.GET, "/api/service-menus/**").permitAll()
```

#### 解決策
`SecurityConfig.java`のパスを実際のエンドポイントに修正：

```java
// メニュー関連（GETは公開、その他はスタッフのみ）
.requestMatchers(HttpMethod.GET, "/api/service-menus/**").permitAll()
.requestMatchers("/api/service-menus/**").hasRole("STAFF")
```

### 5.4 GlobalExceptionHandlerが500を返す

#### 症状
認証エラーや404エラーがすべて500 Internal Server Errorとして返される

#### 原因
`GlobalExceptionHandler`にSpring Security例外のハンドラーがなかった

#### 解決策
以下のハンドラーを追加：

```java
// 403 Forbidden
@ExceptionHandler(AccessDeniedException.class)
public ResponseEntity<Map<String, Object>> handleAccessDeniedException(AccessDeniedException ex) {
    // ...
    return ResponseEntity.status(HttpStatus.FORBIDDEN).body(errorResponse);
}

// 401 Unauthorized
@ExceptionHandler(AuthenticationException.class)
public ResponseEntity<Map<String, Object>> handleAuthenticationException(AuthenticationException ex) {
    // ...
    return ResponseEntity.status(HttpStatus.UNAUTHORIZED).body(errorResponse);
}

// 404 Not Found
@ExceptionHandler(NoHandlerFoundException.class)
public ResponseEntity<Map<String, Object>> handleNoHandlerFoundException(NoHandlerFoundException ex) {
    // ...
    return ResponseEntity.status(HttpStatus.NOT_FOUND).body(errorResponse);
}
```

また、`application.yml`に以下を追加：

```yaml
spring:
  mvc:
    throw-exception-if-no-handler-found: true
  web:
    resources:
      add-mappings: false
```

## 7. トラブルシューティング

### 7.1 EC2に接続できない

```bash
# SSHタイムアウト
ssh: connect to host 18.183.192.121 port 22: Operation timed out
```

**確認事項：**
1. EC2インスタンスが起動しているか
2. セキュリティグループでポート22が開いているか
3. 秘密鍵のパーミッション（`chmod 400 ~/.ssh/nagi5417-key.pem`）

### 7.2 ポート8080にアクセスできない

```bash
curl: (7) Failed to connect to 18.183.192.121 port 8080
```

**確認事項：**
1. セキュリティグループでポート8080が開いているか
2. サービスが起動しているか（`sudo systemctl status reservation`）
3. ファイアウォール設定（`sudo iptables -L`）

### 7.3 アプリケーションが起動しない

```bash
sudo journalctl -u reservation -f
```

**よくあるエラー：**
- データベース接続エラー → PostgreSQLコンテナが起動しているか確認
- ポート競合 → `lsof -i :8080`で確認
- メモリ不足 → EC2インスタンスタイプを確認

### 7.4 Vercelデプロイが失敗する

**確認事項：**
1. Vercelダッシュボードでビルドログを確認
2. `package.json`のビルドスクリプトが正しいか
3. `vercel.json`の構文エラーがないか

### 7.5 フロントエンドでAPIエラー

ブラウザの開発者ツールで確認：

| エラー | 原因 | 解決策 |
|-------|------|--------|
| Mixed Content | HTTPS→HTTP | vercel.jsonのrewritesを確認 |
| CORS | オリジン未許可 | SecurityConfigのCORS設定を確認 |
| 401 Unauthorized | 認証エラー | SecurityConfigのpermitAll()を確認 |
| 404 Not Found | パス不一致 | エンドポイントのパスを確認 |
| 500 Internal Server Error | サーバーエラー | EC2のログを確認 |
