## テーブル定義詳細

### 1. users テーブル

**論理名**: ユーザー
**説明**: システムユーザー（一般ユーザー、スタッフ、管理者）

| カラム名 | 型 | 制約 | 説明 |
|---------|-----|------|------|
| id | BIGSERIAL | PK | ユーザーID（自動採番） |
| google_sub | VARCHAR(255) | UNIQUE, NULL許可 | GoogleのユーザーID（OAuth用） |
| email | VARCHAR(255) | UNIQUE, NOT NULL | メールアドレス |
| password | VARCHAR(255) | NULL許可 | パスワード（BCrypt暗号化）※Google OAuth時はNULL |
| name | VARCHAR(100) | NOT NULL | 氏名 |
| role | VARCHAR(20) | NOT NULL | ロール（USER/STAFF/ADMIN） |
| is_email_verified | BOOLEAN | NOT NULL, DEFAULT FALSE | メールアドレス確認済みフラグ |
| google_access_token | TEXT | NULL許可 | Google OAuthアクセストークン |
| google_refresh_token | TEXT | NULL許可 | Google OAuthリフレッシュトークン |
| created_at | TIMESTAMP | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 作成日時 |
| updated_at | TIMESTAMP | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 更新日時 |

**インデックス**:
- PRIMARY KEY: `id`
- UNIQUE INDEX: `google_sub` (NULL許可のため部分インデックス)
- UNIQUE INDEX: `email`
- INDEX: `role`

**CHECK制約**:
```sql
CHECK (role IN ('USER', 'STAFF', 'ADMIN'))
```

**備考**:
- Google OAuth ユーザー: `google_sub`に値あり、`password`はNULL
- メール/パスワードユーザー: `google_sub`はNULL、`password`に暗号化パスワード
- `google_access_token`, `google_refresh_token`: Google Calendar API呼び出し用
- `is_email_verified`: メール/パスワード登録時、確認メール経由で`TRUE`に変更

---

### 2. service_menus テーブル

**論理名**: サービスメニュー
**説明**: 予約メニューのマスタ（30分コース、60分コース等）

| カラム名 | 型 | 制約 | 説明 |
|---------|-----|------|------|
| id | BIGSERIAL | PK | メニューID（自動採番） |
| name | VARCHAR(100) | NOT NULL | メニュー名（例：「30分コース」） |
| duration_minutes | INTEGER | NOT NULL | 所要時間（分） |
| is_active | BOOLEAN | NOT NULL, DEFAULT TRUE | 有効/無効フラグ |
| created_at | TIMESTAMP | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 作成日時 |
| updated_at | TIMESTAMP | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 更新日時 |

**インデックス**:
- PRIMARY KEY: `id`
- INDEX: `is_active`

**CHECK制約**:
```sql
CHECK (duration_minutes > 0)
```

**備考**:
- 論理削除として`is_active`を使用（物理削除はしない）

---

### 3. slots テーブル

**論理名**: 予約枠
**説明**: スタッフが作成する予約可能な枠

| カラム名 | 型 | 制約 | 説明 |
|---------|-----|------|------|
| id | BIGSERIAL | PK | 枠ID（自動採番） |
| menu_id | BIGINT | FK (service_menus.id), NOT NULL | サービスメニューID |
| start_at | TIMESTAMP | NOT NULL | 開始日時 |
| end_at | TIMESTAMP | NOT NULL | 終了日時 |
| capacity | INTEGER | NOT NULL | 定員数 |
| status | VARCHAR(20) | NOT NULL, DEFAULT 'OPEN' | ステータス（OPEN/CLOSED/CANCELLED） |
| version | BIGINT | NOT NULL, DEFAULT 0 | 楽観ロック用バージョン |
| created_by | BIGINT | FK (users.id), NOT NULL | 作成者（STAFF） |
| created_at | TIMESTAMP | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 作成日時 |
| updated_at | TIMESTAMP | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 更新日時 |

**インデックス**:
- PRIMARY KEY: `id`
- FOREIGN KEY: `menu_id` REFERENCES `service_menus(id)`
- FOREIGN KEY: `created_by` REFERENCES `users(id)`
- INDEX: `start_at` （日時範囲検索用）
- INDEX: `status`
- INDEX: `(menu_id, start_at)` （複合インデックス：メニュー×日時検索）

**CHECK制約**:
```sql
CHECK (start_at < end_at),
CHECK (capacity > 0),
CHECK (status IN ('OPEN', 'CLOSED', 'CANCELLED'))
```

**備考**:
- `version`: 楽観ロック用。予約作成時にインクリメントされる（JPA `@Version`）
- `status`:
  - `OPEN`: 予約受付中
  - `CLOSED`: 予約受付停止（スタッフが手動で停止）
  - `CANCELLED`: 枠自体がキャンセル（スタッフが中止）

---

### 4. reservations テーブル

**論理名**: 予約
**説明**: ユーザーの予約情報

| カラム名 | 型 | 制約 | 説明 |
|---------|-----|------|------|
| id | BIGSERIAL | PK | 予約ID（自動採番） |
| slot_id | BIGINT | FK (slots.id), NOT NULL | 予約枠ID |
| user_id | BIGINT | FK (users.id), NOT NULL | 予約者ID |
| status | VARCHAR(20) | NOT NULL, DEFAULT 'RESERVED' | 予約ステータス（RESERVED/CANCELLED） |
| google_calendar_event_id | VARCHAR(255) | NULL許可 | GoogleカレンダーイベントID |
| created_at | TIMESTAMP | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 予約作成日時 |
| updated_at | TIMESTAMP | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 更新日時 |

**インデックス**:
- PRIMARY KEY: `id`
- FOREIGN KEY: `slot_id` REFERENCES `slots(id)`
- FOREIGN KEY: `user_id` REFERENCES `users(id)`
- INDEX: `user_id` （ユーザーの予約一覧取得用）
- INDEX: `slot_id` （枠の予約数カウント用）
- INDEX: `status`
- INDEX: `(user_id, status)` （複合インデックス：ユーザー×ステータス検索）

**UNIQUE制約（部分）**:
```sql
-- PostgreSQL部分インデックス
CREATE UNIQUE INDEX idx_reservations_unique_active
ON reservations (slot_id, user_id)
WHERE status = 'RESERVED';
```
- 同じユーザーが同じ枠に複数のRESERVED予約を持てない
- CANCELLEDの予約は重複OK（履歴として残すため）

**CHECK制約**:
```sql
CHECK (status IN ('RESERVED', 'CANCELLED'))
```

**備考**:
- `google_calendar_event_id`: Googleログインユーザーのみ値が入る
- キャンセル時もレコードは削除せず、`status`を`CANCELLED`に変更

---

### 5. email_verification_tokens テーブル

**論理名**: メール確認トークン
**説明**: メール/パスワード登録時の確認トークン

| カラム名 | 型 | 制約 | 説明 |
|---------|-----|------|------|
| id | BIGSERIAL | PK | トークンID（自動採番） |
| user_id | BIGINT | FK (users.id), NOT NULL | ユーザーID |
| token | VARCHAR(255) | UNIQUE, NOT NULL | 確認トークン（UUID） |
| expires_at | TIMESTAMP | NOT NULL | 有効期限（24時間後） |
| used_at | TIMESTAMP | NULL許可 | 使用日時（確認完了時に記録） |
| created_at | TIMESTAMP | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 作成日時 |

**インデックス**:
- PRIMARY KEY: `id`
- FOREIGN KEY: `user_id` REFERENCES `users(id)` ON DELETE CASCADE
- UNIQUE INDEX: `token`
- INDEX: `expires_at` （有効期限切れトークンの削除用）

**備考**:
- トークン確認後、`used_at`に現在時刻を記録
- 有効期限切れトークンは定期的に削除（バッチ処理またはログイン時）
- ユーザー削除時はトークンも削除（CASCADE）

## インデックス設計

### 設計方針

1. **PRIMARY KEY**: すべてのテーブルに`id`を設定
2. **FOREIGN KEY**: リレーション整合性のため
3. **UNIQUE INDEX**: 重複防止（email, token等）
4. **検索用INDEX**: 頻繁に検索されるカラム
5. **複合INDEX**: 複数カラムでの検索が多い場合

### インデックス一覧

| テーブル | カラム | タイプ | 目的 |
|---------|--------|--------|------|
| users | id | PRIMARY KEY | 主キー |
| users | google_sub | UNIQUE (部分) | Google OAuth ユーザー検索 |
| users | email | UNIQUE | メールアドレス重複チェック |
| users | role | INDEX | ロール別検索 |
| service_menus | id | PRIMARY KEY | 主キー |
| service_menus | is_active | INDEX | 有効メニュー検索 |
| slots | id | PRIMARY KEY | 主キー |
| slots | start_at | INDEX | 日時範囲検索 |
| slots | status | INDEX | ステータス別検索 |
| slots | (menu_id, start_at) | INDEX (複合) | メニュー×日時検索 |
| reservations | id | PRIMARY KEY | 主キー |
| reservations | user_id | INDEX | ユーザーの予約一覧 |
| reservations | slot_id | INDEX | 枠の予約数カウント |
| reservations | status | INDEX | ステータス別検索 |
| reservations | (user_id, status) | INDEX (複合) | ユーザー×ステータス検索 |
| reservations | (slot_id, user_id) WHERE status='RESERVED' | UNIQUE (部分) | 重複予約防止 |
| email_verification_tokens | id | PRIMARY KEY | 主キー |
| email_verification_tokens | token | UNIQUE | トークン検索 |
| email_verification_tokens | expires_at | INDEX | 有効期限切れ削除 |

## DDL（CREATE TABLE文）

### 1. users テーブル

```sql
CREATE TABLE users (
    id BIGSERIAL PRIMARY KEY,
    google_sub VARCHAR(255),
    email VARCHAR(255) UNIQUE NOT NULL,
    password VARCHAR(255),
    name VARCHAR(100) NOT NULL,
    role VARCHAR(20) NOT NULL CHECK (role IN ('USER', 'STAFF', 'ADMIN')),
    is_email_verified BOOLEAN NOT NULL DEFAULT FALSE,
    google_access_token TEXT,
    google_refresh_token TEXT,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- google_subのUNIQUEインデックス（NULLを許可するため部分インデックス）
CREATE UNIQUE INDEX idx_users_google_sub ON users (google_sub) WHERE google_sub IS NOT NULL;

-- roleインデックス
CREATE INDEX idx_users_role ON users (role);

-- コメント
COMMENT ON TABLE users IS 'ユーザー情報（Google OAuth / メールパスワード）';
COMMENT ON COLUMN users.google_sub IS 'GoogleのユーザーID（OAuth用）';
COMMENT ON COLUMN users.is_email_verified IS 'メールアドレス確認済みフラグ';
COMMENT ON COLUMN users.google_access_token IS 'Google Calendar API用アクセストークン';
```

### 2. service_menus テーブル

```sql
CREATE TABLE service_menus (
    id BIGSERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    duration_minutes INTEGER NOT NULL CHECK (duration_minutes > 0),
    is_active BOOLEAN NOT NULL DEFAULT TRUE,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- is_activeインデックス
CREATE INDEX idx_service_menus_is_active ON service_menus (is_active);

-- コメント
COMMENT ON TABLE service_menus IS 'サービスメニュー（30分コース等）';
COMMENT ON COLUMN service_menus.duration_minutes IS '所要時間（分）';
COMMENT ON COLUMN service_menus.is_active IS '有効/無効フラグ（論理削除用）';
```

### 3. slots テーブル

```sql
CREATE TABLE slots (
    id BIGSERIAL PRIMARY KEY,
    menu_id BIGINT NOT NULL REFERENCES service_menus(id),
    start_at TIMESTAMP NOT NULL,
    end_at TIMESTAMP NOT NULL,
    capacity INTEGER NOT NULL CHECK (capacity > 0),
    status VARCHAR(20) NOT NULL DEFAULT 'OPEN' CHECK (status IN ('OPEN', 'CLOSED', 'CANCELLED')),
    version BIGINT NOT NULL DEFAULT 0,
    created_by BIGINT NOT NULL REFERENCES users(id),
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CHECK (start_at < end_at)
);

-- インデックス
CREATE INDEX idx_slots_start_at ON slots (start_at);
CREATE INDEX idx_slots_status ON slots (status);
CREATE INDEX idx_slots_menu_start ON slots (menu_id, start_at);

-- コメント
COMMENT ON TABLE slots IS '予約枠（スタッフが作成）';
COMMENT ON COLUMN slots.version IS '楽観ロック用バージョン';
COMMENT ON COLUMN slots.status IS 'OPEN: 予約可, CLOSED: 停止, CANCELLED: 中止';
COMMENT ON COLUMN slots.created_by IS '作成者（STAFFユーザー）';
```

---

### 4. reservations テーブル

```sql
CREATE TABLE reservations (
    id BIGSERIAL PRIMARY KEY,
    slot_id BIGINT NOT NULL REFERENCES slots(id),
    user_id BIGINT NOT NULL REFERENCES users(id),
    status VARCHAR(20) NOT NULL DEFAULT 'RESERVED' CHECK (status IN ('RESERVED', 'CANCELLED')),
    google_calendar_event_id VARCHAR(255),
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- インデックス
CREATE INDEX idx_reservations_user_id ON reservations (user_id);
CREATE INDEX idx_reservations_slot_id ON reservations (slot_id);
CREATE INDEX idx_reservations_status ON reservations (status);
CREATE INDEX idx_reservations_user_status ON reservations (user_id, status);

-- 重複予約防止（RESERVED状態のみユニーク）
CREATE UNIQUE INDEX idx_reservations_unique_active
ON reservations (slot_id, user_id)
WHERE status = 'RESERVED';

-- コメント
COMMENT ON TABLE reservations IS 'ユーザーの予約情報';
COMMENT ON COLUMN reservations.google_calendar_event_id IS 'GoogleカレンダーイベントID（Googleログインユーザーのみ）';
COMMENT ON COLUMN reservations.status IS 'RESERVED: 予約中, CANCELLED: キャンセル済み';
```

---

### 5. email_verification_tokens テーブル

```sql
CREATE TABLE email_verification_tokens (
    id BIGSERIAL PRIMARY KEY,
    user_id BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    token VARCHAR(255) UNIQUE NOT NULL,
    expires_at TIMESTAMP NOT NULL,
    used_at TIMESTAMP,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- インデックス
CREATE INDEX idx_email_tokens_expires_at ON email_verification_tokens (expires_at);

-- コメント
COMMENT ON TABLE email_verification_tokens IS 'メール確認トークン（新規登録時）';
COMMENT ON COLUMN email_verification_tokens.token IS '確認トークン（UUID）';
COMMENT ON COLUMN email_verification_tokens.expires_at IS '有効期限（24時間）';
COMMENT ON COLUMN email_verification_tokens.used_at IS '使用日時（確認完了時に記録）';
```
